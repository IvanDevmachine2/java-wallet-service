# Wallet Service

REST приложение для управления балансом кошельков.

## Доступные запросы

**POST /api/v1/wallet** — пополнение (DEPOSIT) и снятие (WITHDRAW) средств
**GET /api/v1/wallets/{WALLET_UUID}** — получение текущего баланса

## Особенности функционала решения

### Конкурентная обработка

Для POST-запроса на один кошелёк используется пессимистичная блокировка (PESSIMISTIC_WRITE) на уровне БД (прописана через Hibernate). Строка кошелька блокируется до завершения транзакции, что избавляет от возможной потери данных при одновременных операциях.

### Единый формат ошибок

Все исключения обрабатываются глобально через controller/GlobalExceptionHandler.java:
- 400 — невалидный JSON, отрицательная сумма, недостаточно средств
- 404 — кошелёк не найден
Ответ всегда содержит поле error с описанием.

### Миграции

Структура БД управляется через Liquibase, проверка на изменения по миграциям применяется автоматически при запуске.

### Контейнеризация

Приложение и PostgreSQL запускаются через docker-compose, параметры вынесены в переменные окружения — меняются в .env без пересборки образов.
Параметры к изменению:
DB_NAME - название БД,
DB_USER - имя пользователя в БД, DB_PASS - пароль для подключения к БД, DB_PORT - порт для подключения к БД, APP_PORT - порт для работы приложения. Прилагается файл .env.example с валидными данными для примера настройки запуска.

### Тесты

Эндпоинты покрыты тестами JUnit 5 + MockMvc, проверяемые действия: успешные операции, нехватка средств, невалидные запросы, несуществующие кошельки.

## Запуск

`cp .env.example .env`
`docker-compose up -d`

Приложение доступно на http://localhost:8081.

## Тестирование

`./mvnw test`

## Стек

Java 17, Spring Boot 3, PostgreSQL 15, Liquibase, Docker, JUnit 5, MockMvc
